# 밀리 플로우 1단계 — 소스 플로우 왁꾸

경로는 `~/.millie-obsidian/config.json` 에서 읽는다 — `vault` 와 `paths`(vault 기준 상대 경로).
본문의 `<키>` = `<vault>/<paths.키>`. 설정에 없는 키는 사용자에게 묻는다.
`<vault>/AGENTS.md` 내용이 아직 컨텍스트에 없으면 먼저 읽는다 (파일명·프론트매터·폴더 승인 규칙).

규칙 원본: `<method_doc>`.
**시작 전에 읽는다** — `🎨 표기 규칙` · `🛠️ 실전 작성 순서` · `🧭 표준 mermaid 템플릿` · `🔁 멀리 떨어진 노드로 위임` · `📐 표준 산출물 구조` · `⚠️ 흔한 함정`.
이 스킬은 순서와 완료 검사만 가진다. 규칙이 바뀌면 원본만 고친다.

## 0. 입력

프로젝트명 · 영역 · 코드 경로(작업 폴더가 vault 밖이면 그 폴더가 기본) · TO-BE 출처(설계 문서 / 회의록). **빠진 것만** 묻는다.
영역이 여러 개면 "영역 문서 + 허브"로 나눌지 먼저 묻는다.

## 1. AS-IS를 코드로 먼저 — 건너뛰기 금지

- 진입 → 수렴점 → 실제 실행(네트워크·토큰·파일·DRM)까지 코드로 추적
- 심볼은 grep으로 끝까지. import · `Frameworks/` · SDK 포함 (개수 단정 금지)
- UI 테스트 코드가 있으면 화면 이동 순서는 거기서 가져온다

## 2. TO-BE 전수 검증 — 출처가 있을 때만

- 설계 문서 + **회의록 전부** + 기획. 설계 문서(위키 등)는 연결된 도구가 있으면 그걸로, 없으면 내용을 달라고 한다. 회의록은 `<meetings>`
- 설계 ≠ 회의면 최신 회의 우선. 충돌 지점에 ⚠️ + 양쪽 출처 + "재확인 필수"
- 🟧 노드마다 출처(설계 문서 링크 · ID / 회의록 **전체 경로**)를 본문에 남긴다

## 3. 그리기

- **분기형 한 장**: 공통 → `◆ 분기점` → 🟦지금 / 🟧신규. 곁가지 · AS-IS/TO-BE 별도 블록 금지
- 노드 = 화면 · 사용자 조작 · 분기 조건. 코드 심볼은 각주로
- 확신 못 하는 분기, 출처 없는 결합 → 🧐 노드 (`unsure` classDef). **추측으로 채우지 않는다**
- 멀리 위임은 번호 라벨 + parallelogram 안내 노드

## 4. 쓰기

위치: 기본 `<flow_output>/🧭 <프로젝트> <영역> 플로우.md`.
`<projects>/<이름>/` 에 두려면 `<vault>/AGENTS.md` 규칙대로 **먼저 승인** (파일명 · 목적 · 기존 5개로 안 되는 이유).

```yaml
---
type: flow
project: <프로젝트>
created: <오늘 YYYY-MM-DD>
tags: [flow, project/<프로젝트-공백은-하이픈>]
---
```

섹션 순서는 원본 `📐 표준 산출물 구조` 의 "영역 문서(소스) 내부" 그대로.
맨 아래 `## 📌 미확정 항목 (= QA 엣지 후보)` — `- [ ]` 체크박스, 본문 🧐 와 1:1.

## 5. 완료 검사 — 하나라도 걸리면 고치고 다시

- [ ] 본문 🧐 수 = `📌 미확정 항목` 수 (grep으로 센다)
- [ ] 🟧 노드마다 출처 있음
- [ ] mermaid 노드에 코드 심볼 · URL · file:line 없음
- [ ] AS-IS/TO-BE가 한 그림, `◆` 분기점 있음
- [ ] 파일명에 프로젝트명 · 프론트매터 `created` + `project/` 태그
- [ ] `<archives>` · `<store>` 문서로 가는 링크 없음

`ai-check` 스킬이 있으면 결론 직전에 돌린다.
보고: 파일 경로 · 🧐 N개(= QA 엣지 후보) · 다음은 `flow-fill` 스킬.
