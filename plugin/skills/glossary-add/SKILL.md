# 용어집 추가

경로는 `~/.millie-obsidian/config.json` 에서 읽는다 — `vault` 와 `paths`(vault 기준 상대 경로).
본문의 `<키>` = `<vault>/<paths.키>`. 설정에 없는 키는 사용자에게 묻는다.

형식 원본: `<vault>/AGENTS.md` 의 `## 용어집 추가 규칙`. 폴더: `<glossary>`, 인덱스: `<glossary_index>`.

## 1. 근거 확인

- vault를 grep해서 그 용어가 쓰인 곳과 출처(정책 문서 · 회의록 · 코드)를 확인
- 이미 있으면 추가하지 않는다. 기존 정의와 다르면 사용자에게 보여주고 묻는다
- 뜻이 하나로 안 잡히거나 근거가 없으면 → 추가하지 않고 `<glossary_index>` `## 채울 것` 에
  `- [ ] **<용어>** — <왜 못 정했나>`

## 2. 주제 파일 고르기

- `<glossary_index>` 표에서 주제를 고른다
- 맞는 주제가 없으면 새 주제 파일을 **제안** (파일명 · 들어갈 용어) → 승인 후 생성
- 풀네임만으로 끝나는 일반 약어는 `<glossary_index>` 의 `## 일반 약어` 표

## 3. 쓰기 — 3줄 고정

```markdown
## <용어>

<풀네임> — <뜻 한 줄>.

> <비유 1~2줄>
```

- 비유는 사용자가 직접 겪는 일상에서. 0.5초 안에 "맞아/틀려" 판정되는 것만. 기술로 기술을 비유하지 않는다
- 불릿 · 표 · 근거 링크 · 코드 금지. 상세는 정책 문서로

새 주제 파일이면:

```markdown
---
type: glossary
created: <오늘 YYYY-MM-DD>
tags: [glossary, <주제>]
---

[[<glossary_index 의 vault 상대 경로, 확장자 없이>|📖 용어집]]

# <이모지> <주제> 용어
```

## 4. 인덱스 갱신

- `<glossary_index>` 표의 해당 주제 행 `용어` 칸 끝에 ` · <용어>`
- 새 주제 파일이면 표에 한 줄 추가
- `## 채울 것` 에 있던 용어면 그 줄을 지운다

## 5. 검사

- [ ] 추가한 블록 = 제목 + 정의 한 줄 + `>` 비유 (빈 줄 빼고 3덩어리)
- [ ] 인덱스 표에 반영됨
