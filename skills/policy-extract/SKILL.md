# 정책 추출 — 영역별 전수

경로는 `~/.phantom-obsidian/config.json` 에서 읽는다 — `vault` 와 `paths`(vault 기준 상대 경로).
본문의 `<키>` = `<vault>/<paths.키>`. 설정에 없는 키는 사용자에게 묻는다.
`<vault>/AGENTS.md` 내용이 아직 컨텍스트에 없으면 먼저 읽는다.

정책은 코드에 암묵적으로 흩어져 있다. 한 번 훑으면 갈래가 빠지고, 빠지면 정의가 틀어진다.
**단일 스윕 금지.**

## 0. 범위 좁히기

- 영역 하나 = 문서 하나. `<policy_index>` 표에 있는 영역이면 그 문서를 보강, 없으면 새 문서
- 코드 경로: 인덱스 상단에 적힌 경로. 다르면 묻는다
- 영역을 하위 묶음(파일 그룹)으로 쪼개고, **쪼갠 목록을 먼저 보여준다**

## 1. 정독

- 묶음마다 파일을 **처음부터 끝까지.** 분기 · 상수 · enum · 임계값 · 주석 처리된 코드를 하나씩 열거
- 하위 에이전트를 띄울 수 있으면 묶음별로 병렬. 발췌만 읽는 탐색 모드는 쓰지 않고 파일 전체를 읽게 지시. 각자 "열거 목록 + 파일:라인"만 반환
- 묶음이 10개를 넘으면 여러 번에 나눠 돌릴지 묻는다
- 주석 처리 · 비활성 코드는 정책이 아니다. 단 "비활성"으로 적고 `git log` 로 언제 · 누가 껐는지 붙인다

## 2. 판정

- ✅ 코드로 100% 증명
- ⚠️ 코드엔 있는데 의미 · 값 해석 필요, 기본값 불일치, 서버 판정(클라에 값 없음) → **정의 필요**
- 🚫 있을 줄 알았는데 없음 → **반드시 적는다** (정책 정의 1순위)
- 근거 없는 건 쓰지 않는다. "보통 이렇다"는 회사 정책이 아니다

## 3. 그리기

- 정책 = mermaid flowchart. `([유저: ...])` 로 시작 → 분기 → 결과
- 차단 · 경고 classDef는 같은 폴더의 기존 정책 문서 것을 재사용
- 예외 경로는 흐름 아래 `> ※` 한 줄
- 표는 값 목록(상수)일 때만

## 4. 쓰기

위치: `<policy_index>` 와 같은 폴더. 파일명 `<이모지> <영역> 정책.md`.

```yaml
---
type: policy
area: <영역>
created: <오늘 YYYY-MM-DD>
tags: [policy]
---
```

섹션: 네비(정책 인덱스 · 관련 QA) → `흐름 N — <유저 행동>` → `그 외 확정 정책` → `📑 코드 근거` → `⚠️ 정의 필요`
기존 문서 보강이면 `created` 는 그대로 둔다.

인덱스 갱신: `📂 정책 문서` 표 한 줄 + `⚠️ 정의 필요` 집계에 새 항목.

## 5. 완료 검사

- [ ] 묶음별 "읽은 파일 수 / 열거 항목 수" 보고 — 0인 묶음이 있으면 다시
- [ ] 모든 ✅ 에 파일:라인
- [ ] 🚫 를 확인한 항목이 적혀 있음 (없으면 "🚫 확인 0건"이라도 명시)
- [ ] 본문 ⚠️ 와 인덱스 `⚠️ 정의 필요` 일치

`ai-check` 스킬이 있으면 결론 직전에 돌린다. 사용자가 "이게 다야?" 하면 `ai-log` 스킬이 있으면 적립하고, 빠진 묶음을 다시 정독.
