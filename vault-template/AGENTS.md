# Phantom Vault — 작업 규칙

## 핵심 6줄

1. **문서는 짧게.** 결론·핵심 먼저, 근거·상세는 `<details>` 또는 문서 하단. 길면 안 읽는다.
2. **폴더 = 상태.** `1. Projects`(진행) / `5. Store`(중지) / `4. Archives`(종료). 서로 링크 금지.
3. **파일명에 프로젝트명 필수.** `📓 <이름> Overview.md`, `🚨 <이름> 이슈.md`, `✅ <이름> QA.md`.
4. **`1. Projects/` 안에 새 파일은 승인 없이 만들지 않는다.** ↓ 아래 상세
5. **새 파일 프론트매터에 `created` + 프로젝트 태그 필수.** `created: 2026-08-03`, `tags: [project/QR-로그인]`
6. **회의록 링크는 전체 경로로.** 날짜 파일명 중복 있음.

## 프로젝트 필수 항목 (활성 프로젝트)

`📓 <이름> Overview.md` 에 아래 3종이 있어야 한다. 비어 있으면 로그·회의·작업이 오갈 때마다 리마인드가 뜬다.

| 항목 | 위치 | 기준 |
|---|---|---|
| ✅ 완료 조건 | `## ✅ 완료 조건` | 검증 가능한 문장 1개 이상 |
| 🏁 마일스톤 | `## 🏁 마일스톤` | 목표일(`YYYY-MM-DD`)이 붙은 항목 1개 이상 |
| 📆 완료일 | frontmatter `due:` | 날짜. `9999`·빈칸 = 미설정 |

- 점검: `python3 .scripts/project_lint.py` (읽기 전용). 채우기: `/obsidian-project-scope <이름>`
- 리마인드 경로: 개발일지 알림(`추가 검토사항`, 선택) · AI 세션 훅(phantom-vault) · `📓 Projects` 대시보드 `필수 항목` 열
- 날짜·조건을 사용자 답 없이 지어내 채우지 않는다. 비어 있는 채로 두는 게 맞다
- frontmatter: `status: active|paused|done` (Store 는 `paused` + `tags: [project/paused]`)
- 분류용 칸(`00. 미분류` · `01. Daily`)은 프로젝트가 아니라 점검에서 뺀다

## 4분류와 폴더 생성 (프롬프트 기록)

기록할 가치가 있는 프롬프트·작업은 **Projects / Areas / Resources / Archives 중 정확히 한 곳**에 들어간다
(끝이 있나 → Projects · 지속 책임 → Areas · 참고용 → Resources · 끝났나 → Archives. `5. Store` 는 Projects 의 중지 상태).

- **폴더·노트 생성은 사용자 허락 후에만.** 기존에서 먼저 찾고(비슷한 이름 포함), 정말 없을 때만 한 줄로 묻는다. 허락 전에는 `00. 미분류` 개발일지 로그에 `[분류 대기: ...]` 로 임시 기록한다
- 보관(`4. Archives` 로 이동)도 허락 필요. 거절된 이름은 다시 묻지 않는다
- 도구: `scripts/vault_record.py` (`devlog` · `tick` · `area` · `resource` · `match` · `new` · `archive`) — `vault-record` 스킬

## 프로젝트 폴더 신규 파일 = 승인 필요

`1. Projects/<이름>/` 에는 프로젝트 생성 시 만들어지는 **5개 파일만** 기본으로 존재한다:

| 파일 | type |
|---|---|
| `📓 <이름> Overview.md` | `project` |
| `🚨 <이름> 이슈.md` | `issues` |
| `🏛️ <이름> 구성도.md` | `diagram` |
| `🔀 <이름> 시퀀스.md` | `sequence` |
| `📐 <이름> 규격서.md` | `spec` |

**이 5개 외의 파일을 프로젝트 폴더에 만들 때는 반드시 먼저 물어본다.** 만들 파일명·목적·왜 기존 5개로 안 되는지를 한 줄씩 대고 승인받는다.
기존 5개 파일에 내용을 **추가·수정**하는 건 승인 불필요.
`3. Resources/`, `Templetes/`, `.scripts/` 등 프로젝트 폴더 밖은 이 규칙 대상 아님.

## 파일 만들 때

- `created: YYYY-MM-DD` — 만든 날짜. 이후 수정해도 그대로 둔다
- `tags: [project/<이름>]` — **태그는 프로젝트 단위**. 공백은 하이픈으로 (`project/QR-로그인`)
- 프로젝트에 안 속한 문서는 성격 태그 (`[ticket]`, `[report, weekly]` 등)

## 용어집 추가 규칙

`3. Resources/02. 용어집/` 에 용어를 넣을 때 **형식은 3줄 고정**이다.

```markdown
## API Gateway

외부 요청을 받아 인증·라우팅을 한 곳에서 처리하는 입구 서버.

> 건물 안내데스크. 방문자는 여기서 확인받고 원하는 사무실로 안내받는다.
```

- `## 용어` → **한 줄 정의**(풀네임 — 뜻) → **`>` 비유 1~2줄**. 그 외 불릿·표·근거 링크 금지
- 비유는 사용자가 직접 겪는 일상에서. 0.5초 안에 "맞아/틀려" 판정되는 것만
- 상세·근거·코드 라인은 정책 문서나 대조 문서에 쓰고, 용어집에는 넣지 않는다
- 용어는 **주제별 파일**에 모은다 (`🔐 인증·보안 용어.md` 처럼). 새 주제면 새 파일 + `📖 용어집.md` 표에 한 줄 추가
- 뜻이 하나로 안 잡히거나 근거가 없으면 넣지 말고 `📖 용어집.md` 의 "채울 것"에 남긴다

## 안 하는 것

- 추측으로 정책·코드 동작 쓰기 (파일:라인 근거 없으면 쓰지 않음)
- Projects ↔ Store ↔ 회의 카테고리 허브 크로스링크
- 표로 정책 나열 (정책은 mermaid 흐름도)

| 폴더 | 역할 |

| `1. Projects/` | 활성 프로젝트. `📓 Projects.md`가 dataview 대시보드 |

| `3. Resources/` | `00. Reference`(기준 자료·정책) `01. Meeting` `02. 용어집` `02. 주간보고` `03. 개발일지` `99. QA` |

| `5. Store/` | 임시중지. `status: paused` + `tags: [project/paused]` |
| `Templetes/` | Templater 스크립트 |
| `.scripts/` | 자동화 스크립트 (`project_lint.py` 등) |

`03. 개발일지/` 하위 폴더명은 **`<프로젝트> 개발일지`** — 종료 시 `4. Archives/<프로젝트>/` 안으로 폴더째 옮기므로
프로젝트명만이면 상위 폴더와 구분이 안 된다 (`4. Archives/SNS로그인/SNS로그인 개발일지/` 가 기준).
로그·이슈 인박스와 이동 히스토리 4개 파일은 이 폴더 루트에 같이 둔다.

### 프론트매터 규약

- 프로젝트 Overview: `type: project`
- 이슈: `type: issues` + `project: <이름>`
- 회의 카테고리 허브: `type: meeting-hub` + `tags: [meeting/hub]`

dataview는 파일명이 아닌 `type`으로 집계 → 파일명 바꿔도 안 깨짐.

### 맥락 분리 이유

그래프 뷰에서 클러스터 응집이 목적. Store(중지)와 Projects(진행)를 엮으면 활성/정지 구분이 흐려진다. 회의 카테고리 허브도 프로젝트 맥락과 분리.

### 문서 2레이어 (팬텀 플로우 산출물)

- **소스 플로우** `🧭 <영역>` — 코드 용어(메서드·심볼) 기준. AS-IS→TO-BE 추적용
- **정책 QA** `✅ <영역> QA` — 정책·사용자 용어로 재작성. 코드 심볼은 하단 "소스 매핑" 표로만

정책 문서는 ✅확정 / ⚠️해석필요 / 🚫부재 로 구분하고, 부재를 반드시 명시한다.
