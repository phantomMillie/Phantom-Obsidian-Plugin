인자: `$ARGUMENTS`

`📓 Projects` 대시보드의 진행률은 Overview `## 📋 세부 목표` 의 체크박스로 계산된다.
템플릿 자리표시(`- [ ] 세부 목표` 3줄)만 있으면 **분모가 가짜다** — 진행률이 항상 0%.
이 커맨드는 그 분모를 사람에게 물어서 확정한다.

## 1. 대상 정하기

- 인자 없음 / `--all` → 프로젝트별 분모 상태 표만 출력하고 멈춘다.
  `1. Projects/*/📓 * Overview.md` 의 `## 📋 세부 목표` 체크박스 수 · 자리표시 여부 · 마지막 수정일.
  자리표시인 프로젝트를 **우선순위 순으로 3개까지** 제시하고 어느 걸 할지 묻는다.
- 프로젝트명 있음 → 그 프로젝트만.

## 2. 재료 수집 (읽기만)

| 재료 | 위치 |
|---|---|
| 목표·현재 상태·남은 것 | `1. Projects/<이름>/📓 <이름> Overview.md` |
| 미완료 이슈 | `1. Projects/<이름>/🚨 <이름> 이슈.md` 의 `- [ ]` |
| 최근 작업 | `3. Resources/03. 개발일지/<이름> 개발일지/` 최근 14일 |
| 할 일 | `3. Resources/07. TODO/*.md` 에서 `[<이름>]` 붙은 줄 |
| 결정·합의 | `3. Resources/01. Meeting/` 에서 `project: <이름>` |

읽은 것에서 **분모 후보**를 뽑는다. 없는 건 만들지 않는다 — 재료에 근거 없는 항목은 질문으로 돌린다.

## 3. 질문 (AskUserQuestion, 재료로 구체화해서)

아래 6개를 재료에 맞춰 다듬어 묻는다. 한 회차에 4개까지 → 2회차로 나눈다.
**선택지는 반드시 재료에서 뽑은 실제 문구로 만든다.** 일반론 선택지는 금지.

1. **완료 기준** — 무엇이 되면 이 프로젝트 끝인가. Overview 목표에서 후보 2~3개 제시
2. **마일스톤** — 배포/단계가 몇 개이고 각 범위는 무엇인가 (없으면 단일)
3. **분모 후보 승인** — 재료에서 추린 큰 덩어리 N개를 그대로 보여주고, 빠진 것·뺄 것
4. **이미 끝난 것** — 후보 중 완료된 항목 (→ `- [x]`)
5. **남에게 달린 것** — 정책 답변·타팀 대기 항목을 분모에 넣을지.
   넣으면 내 통제 밖 요인으로 진행률이 멈춘다 → 기본은 **분모에서 빼고 별도 표기**
6. **쪼개기 단위** — 반나절~2일로 쪼갤지, 큰 덩어리로 둘지.
   항목 크기가 들쭉날쭉하면 진행률이 거짓말을 한다

## 4. 기입

프로젝트 필수 3종을 먼저 채운다 (`python3 .scripts/project_lint.py --project <이름>` 이 비었다고 알리는 것들):

- `## ✅ 완료 조건` ← 질문 1의 답. 검증 가능한 문장으로 `- [ ] ` 1개 이상
- `## 🏁 마일스톤` ← 질문 2의 답. 각 항목에 목표일 `YYYY-MM-DD` 필수 (`- [ ] 1차 배포 — 2026-11-05`)
- frontmatter `due:` ← 최종 완료일. 모르면 마일스톤 중 가장 늦은 날짜를 **제안**하고 확인받는다 (임의 확정 금지)

그다음 `## 📋 세부 목표` 를 다시 쓴다. 자리표시 3줄은 지운다.

```markdown
## 📋 세부 목표
> 진행률 분모. `📓 Projects` 대시보드가 이 섹션 체크박스로 계산한다.
> 항목 크기는 비슷하게. 남에게 달린 건 체크박스 없이 `⏸` 로 뺀다.

### <마일스톤 1>
- [x] <원문 그대로>
- [ ] <원문 그대로>

### <마일스톤 2>
- [ ] <원문 그대로>

⏸ 대기 (분모 제외)
- <정책 답변 대기 항목> ← 누가 결정해야 하는지 같이 적는다
```

- **원문 문구를 유지한다.** 요약·추상화하면 나중에 무슨 일인지 못 알아본다
- 마일스톤 없으면 `###` 없이 평평하게
- `## 📆 배포` 날짜가 `9999-01-01` 인데 확정 날짜를 알게 됐으면 같이 갱신 (대시보드 배포월이 여기서 나온다)
- 이슈 문서·TODO 원문은 **건드리지 않는다**. 저쪽이 원시데이터, 여기가 정리본

## 5. 보고

기입 후 한 줄씩 요약한다 — `항목 → 출처(이슈/TODO/개발일지/회의)`.
분모 개수·완료 개수·진행률을 마지막에 한 줄. 대시보드에서 보일 값과 같아야 한다.

## 안 하는 것

- 재료에 근거 없는 항목 생성 (질문으로 돌린다)
- 분모를 잘게 쪼개 진행률 낮추기 / 뭉뚱그려 높이기
- `1. Projects/` 에 새 파일 만들기 — 기존 5개 파일만 고친다
- 날짜·완료 조건을 사용자 답 없이 채우기 — 비어 있으면 리마인드가 계속 뜨는 게 정상 동작이다
